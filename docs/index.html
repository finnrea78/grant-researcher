Grant Scout · Architecture Spec

Deployment Architecture

Date: 2026-04-01 Status: Draft Author: Finn Rea + Claude

0 Overview

Grant Scout is a grant-matching pipeline for academic researchers. This document defines the deployment architecture, cost optimisation strategy, and staged rollout plan for moving from a local monorepo to a production SaaS product.

👤
Individual
Single academic researcher. Own data, own pipeline runs.
🏛️
Department
Admin manages researchers in one department. Bulk operations.
🎓
University
Manages multiple departments. Reporting & analytics.

2 Database Model

Supabase PostgreSQL Tables
Table Key fields Purpose
organisations id, name, tier, parent_org_id University / department hierarchy
users id, org_id, role, email Supabase Auth users + org membership
researcher_sessions id, user_id, org_id, researcher_name Each researcher's pipeline context

Row-Level Security (RLS)

Data isolation enforced at the database level — no application logic required.

RoleCan see
ResearcherRows where user_id = auth.uid()
Department adminRows where org_id = their org
University adminRows where org_id = their org OR parent_org_id = their org
Any authenticated userAll rows in grants table (shared data)

3 Pipeline Architecture

Two separate systems replace the current monolithic Agent SDK pipeline.

System A Harvester — background, scheduled

Runs on a cron schedule. No Agent SDK. Pure Node.js code.

⏱ Cron trigger (daily / weekly per source)
↓
Layer 1 — API connectors
UKRI, NSF, EU Horizon APIs
fetch() → parse JSON → upsert
Cost: free
↓
Layer 2 — Web scrapers
Cheerio for known HTML structures
fetch() → parse → upsert
Cost: free
↓
Layer 3 — AI enrichment (rare)
Messy pages only. Single messages.create()
Structured output schema
Cost: ~$0.01–0.03/page
↓
Supabase grants table (shared, all users)
System B User pipeline — on-demand

Triggered when a user uploads their CV. Code does I/O. Claude does thinking.

📄 CV + publications + goals uploaded
↓
Profile step
Code reads docs → 1× messages.create() → Code writes profile.json
~$0.05–0.10
↓
Match step
Tiered matching — see diagram below
~$0.03–0.10
↓
Propose step
Code reads profile + grant → 1× stream() → Code writes proposal.md
~$0.05–0.15
↓
Results in Supabase + proposals on volume
⚡ Tiered Matching — Recall-Optimised

Missing a relevant grant is worse than surfacing irrelevant ones. Three tiers ensure nothing is missed.

T1
Code-based pre-filter Free
Filter by discipline keywords, country eligibility, career stage, deadline not passed.
Intentionally permissive — 500+ grants → ~50–100 candidates
↓
T2
AI scoring — per-grant ~$0.02–0.08
Batches of 5–10 grants per API call. Each grant gets individual attention.
Structured output: score 0–100 + reasoning per grant.
↓
T3
AI synthesis — one call ~$0.01–0.03
Send all scored results → Claude returns ranked list with strategic recommendations.

4 Cost Per Pipeline Run

Step Agent SDK (current) Raw API (target) Savings
Profile ~$1–3 ~$0.05–0.10 95%
Scan / Harvest ~$2–8 ~$0 (code harvester) 100%
Match ~$1–3 ~$0.03–0.10 97%
Propose ~$1–3 ~$0.05–0.15 95%
Total ~$5–17 ~$0.13–0.35 ~97%

Agent SDK kept for premium features (grant discovery, deep proposals) on higher tiers where the cost is justified.

5 API Routes

MethodRouteWhat it does
POST/api/sessionUpload CV + additional docs. Create session in Supabase.
POST/api/session/[name]/profileClaude API: read all raw docs → build profile.json (streaming)
POST/api/session/[name]/matchClaude API: tiered matching against Supabase grants table (streaming)
GET/api/session/[name]/matchesRead match_results from Supabase
POST/api/session/[name]/proposeClaude API: draft proposal for selected grant (streaming)
GET/api/session/[name]/proposalRead proposals from volume
GET/api/session/[name]/statusRead pipeline_runs from Supabase

All routes check Supabase Auth JWT before processing. Pipeline status tracked in pipeline_runs table.

6 Staged Rollout

Stage 1 — Now
Demo deployment
  • 1a: Deploy current code to Railway. Set ANTHROPIC_API_KEY. Mount volume. Working URL, no auth.
  • 1b: Create Supabase project. Add auth + basic tables. Add auth middleware to routes.
  • Result: live URL, users can sign up, upload CV, run full pipeline.
Stage 2 — Cost Reduction
Replace Agent SDK with raw Claude API
  • Profile step first (simplest — single input, structured output)
  • Match step → tiered matching, read grants from Supabase
  • Propose step → single streaming API call
  • Remove @anthropic-ai/claude-agent-sdk dependency
  • Add grants + match_results tables to Supabase
Stage 3 — Scale
Harvester + admin tools
  • Build harvester service (API connectors + scrapers)
  • Set up cron jobs on Railway for scheduled harvesting
  • Add admin dashboard (department/university views)
  • Bulk pipeline operations for admins
  • Job queue for background processing (BullMQ/Redis)
Stage 4 — Premium
Agent features + enterprise auth
  • Agent-powered grant discovery (higher tiers)
  • Deep proposal assistance with cross-document reasoning
  • Reporting and analytics for university admins
  • SSO (SAML/OIDC) for university-wide tier

7 End-to-End Implementation Checklist

Stage 1a — Railway deploy

  • ○ Create Railway project from monorepo root
  • ○ Set build command: npm run build -w core && npm run build -w grant-researcher
  • ○ Set start command: npm run start -w grant-researcher
  • ○ Add ANTHROPIC_API_KEY env var
  • ○ Mount persistent volume at /data
  • ○ Update core/data path resolution to use /data
  • ○ Verify full pipeline runs end-to-end on Railway URL

Stage 1b — Supabase auth

  • ○ Create Supabase project
  • ○ Create organisations, users, researcher_sessions, pipeline_runs tables
  • ○ Add RLS policies per table
  • ○ Add @supabase/supabase-js to grant-researcher package
  • ○ Create src/lib/supabase.ts client
  • ○ Add src/middleware.ts — check JWT on all /api/session/* routes
  • ○ Add sign-up / sign-in pages
  • ○ Add SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY to Railway
  • ○ Update /api/session route to create Supabase session record
  • ○ Verify: second user cannot see first user's data

Stage 2 — Raw Claude API

  • ○ Add @anthropic-ai/sdk dependency
  • ○ Create src/lib/claude.ts — Anthropic client + streaming helper
  • ○ Refactor profile route: Node.js reads docs → messages.create() with structured output → Node.js writes profile.json
  • ○ Add grants + match_results tables to Supabase
  • ○ Refactor match route: read profile + grants from Supabase → tiered matching → write match_results
  • ○ Refactor propose route: Node.js reads profile + grant → messages.stream() → SSE to browser
  • ○ Delete scan route (replaced by harvester)
  • ○ Remove @anthropic-ai/claude-agent-sdk dependency
  • ○ Verify cost per run in Anthropic dashboard: target <$0.35

Stage 3 — Harvester

  • ○ Create core/src/harvester/ directory
  • ○ Build UKRI Gateway API connector
  • ○ Build NSF API connector
  • ○ Build generic Cheerio web scraper for known funder pages
  • ○ Build AI enrichment pipeline for messy pages (single API calls)
  • ○ Set up Railway cron jobs for each source
  • ○ Add admin dashboard pages (Next.js routes, Supabase queries)
  • ○ Implement job queue for bulk operations (BullMQ)

Stage 4 — Premium features

  • ○ Agent-powered grant discovery feature (gated to higher tiers)
  • ○ Deep proposal assistance with multi-document context
  • ○ University admin reporting + export
  • ○ SAML/OIDC SSO integration
